# Synthetic verification results

The ten cases in [demo-results.json](demo-results.json) were generated by `demo.py`, written as H5AD, reopened with AnnData, and checked against direct source-dtype densification followed by float32 conversion. All ten agreed with that direct computation, and all ten source files retained identical bytes after preflight.

Five cases pass the narrow numeric check; five fail as intended. In particular:

* Two individually finite float32 values at the same sparse coordinate produce a nonfinite logical value when added.
* Two positive int8 stored values produce a negative logical value through integer wrap.
* Float64 cancellation produces finite zero before conversion, even though casting each stored entry separately produces infinities.
* The float64 rounding example retains a logical value of one. Casting the entries before adding them is a different computation.

The standalone unittest suite passes 15 tests, including ten fixture subcases and eight randomized CSR/CSC/dtype combinations that cross block boundaries. It also verifies malformed-storage refusal, working-array refusal, CLI exit codes, input-byte preservation, and an end-to-end demonstration generated into a new directory.

Reproduce from a fresh checkout with the commands in the README. The direct oracle uses AnnData to read the complete fixture and SciPy/NumPy to ingest it; the tool under test uses h5py and bounded blocks. Both use the pinned numeric libraries. This is an independent check of the traversal and conversion order, not an independent reimplementation of sparse arithmetic and not a full official-scoring run.

No Challenge dataset was downloaded or included. No prediction was sent to a leaderboard. The examples establish software behavior on invented data, not the prevalence of this problem in Challenge files or its effect on a competition score.
